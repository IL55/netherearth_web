# ADR 1. Record architecture decisions

Date: 2026-05-19

## Status

Accepted

## Context

We need to record the architectural decisions made on this project.

## Decision

We will use Architecture Decision Records, as [described by Michael Nygard](http://thinkrelevance.com/blog/2011/11/15/documenting-architecture-decisions).

---

We will keep a collection of records for "architecturally significant" decisions: those that affect the structure, non-functional characteristics, dependencies, interfaces, or construction techniques.

Each record describes a set of forces and a single decision in response to those forces. Numbers will not be reused. If a decision is reversed, we keep the old ADR but mark it as superseded.

## Consequences

ADRs provide historical context for future developers even after a decision has been revisited or reversed. See Michael Nygard's article linked above.
